# 将棋

ブラウザだけで指せる将棋です。持ち駒、成り、王手、詰み、二歩、打ち歩詰め、千日手まで、ルールに沿って動けます。対局は次の3つです。

- オンライン対局（部屋コードと共有リンク）
- コンピュータ対戦（易しい / 普通 / 強い）
- 同じ画面で交互に指す

画面の文言は日本語です。サーバー代はかかりません。

## 手元で動かす

```bash
npm install
npm test
npm run dev
```

開発サーバーは <http://127.0.0.1:43123> です。

```bash
npm run build
npm run preview
```

`dist/` が静的ファイル一式です。

## 無料で公開する

`vite build` の成果物は、どの静的ホストにも置けます。`base` は `./` なので、サブディレクトリでも動きます。

- **GitHub Pages**: `dist/` を公開する。リポジトリの Pages 設定で GitHub Actions から `npm ci && npm run build` し、`dist` をアップロードする。
- **Cloudflare Pages**: ビルドコマンド `npm run build`、出力ディレクトリ `dist`。
- **Vercel の無料枠**: フレームワークは Vite。出力は静的サイト。

環境変数も API キーも要りません。

## オンライン対局の仕組みと限界

オンラインは **公開 MQTT ブローカーへの WebSocket** です。部屋ごとにトピック `shogi/koma/v1/{部屋コード}` を使い、両者はそこへ指し手を流します。使っている入口は次の順で、つながったものだけを使います。

1. `wss://broker.emqx.io:8084/mqtt`
2. `wss://broker.hivemq.com:8884/mqtt`
3. `wss://test.mosquitto.org:8081`

部屋を作った側が先手で、局面の決定権を持ちます。後手は手を送り、先手が合法なら採用して全体を返します。最新の局面は retain してあるので、同じタブを再読み込みしたあとも追いつきやすくしています。

この方式を選んだ理由は、**自分のサーバーが要らず、NAT の穴あけも要らない**からです。WebRTC（PeerJS など）は無料のシグナリングに依存したうえで、対称 NAT だと繋がらないことがあります。MQTT なら両方とも外向きの WSS だけで足ります。

限界は次のとおりです。

- 公開ブローカーなので、部屋コードを知っていれば指し手は読めます。秘密の対局には向きません。
- ブローカーが落ちる、混む、メッセージを捨てることがあります。3つに切り替えますが、保証はありません。
- 配信は QoS 0 です。取りこぼしたときは、先手が配る局面で後手が合わせます。
- 先手のタブが閉じたまま戻らないと、対局は止まります。後手は再接続を待ちます。
- 部屋コードは6文字です。偶然の衝突はほぼ起きませんが、理論上はありえます。
- 千日手の履歴は、再接続で局面だけを受け取った場合にはリセットされます。通常の1局の途中再接続では、指し手リストを再生するので維持します。
- 連続王手の千日手は「同一局面が4回目に現れ、その間片方だけが毎回王手をかけていたら、その人が負け」という簡略版です。

## コンピュータ

読みは Web Worker 内のアルファベータです。反復深化、置換表、取り合いと成りの優先、時間切れで打ち切ります。

| 強さ | 目安の深さ | 時間の上限 |
| --- | --- | --- |
| 易しい | 2 | 0.7秒。近い評価の手を散らします |
| 普通 | 3 | 1.6秒。取り合いの読みを少し足します |
| 強い | 4 | 2.8秒。同じ |

駒の価値と位置で評価しています。序盤の定跡本はありません。数秒以内に手を返します。

## ルールで入っているもの

駒の動き、成り（任意と強制）、持ち駒、二歩、行き所のない駒、打ち歩詰め、自玉を王手に残す手の禁止、王手、詰み、投了、千日手です。
